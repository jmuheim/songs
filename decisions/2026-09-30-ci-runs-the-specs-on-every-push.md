## 2026-09-30 — CI runs the specs on every push

**Context:** The RSpec suite (unit, integration, golden-HTML and browser specs) only ever ran on the machine of whoever remembered to run it. Nothing caught a broken push, and a later change — deploying only after green tests — needs a green run to hang off.

**Decision:** A GitHub Actions workflow (`.github/workflows/test.yml`) runs `bundle exec rspec` on every push to any branch and on every pull request. It installs Ruby 3.2, Pandoc 3.9.0.2 pinned as the official `.deb`, and the `multiplex-server/` Node dependencies via `npm ci`. Chrome (for Cuprite) and Node are already on the `ubuntu-latest` runner. The workflow was adapted from `axipedia`'s `test.yml`, dropping everything Songs has no use for: ImageMagick, WeasyPrint, veraPDF, poppler, `librsvg`, `apache2-utils`, dummy multiplex credentials and the pre-build step.

To make `bundle install` work on the Linux runner, `x86_64-linux` was added to `Gemfile.lock`'s `PLATFORMS` (`bundle lock --add-platform x86_64-linux`); the lockfile previously pinned only `arm64-darwin`, so CI would have failed to resolve nokogiri's native gem.

**Reasoning:** The repo is public, so Actions minutes are free — there is no reason to gate which branches run; running on every push is the simplest rule that never lets an untested commit through. Pandoc is pinned to the exact version the committed golden fixtures were built with (the current local `3.9.0.2`), because the golden-HTML specs compare Pandoc's byte-for-byte output — a different version would fail them for reasons unrelated to any real change. No `./build` step is needed before the suite: every browser and golden spec calls `FixtureBuilder.build!` itself and uses the fixed test multiplex token, so the run never depends on the committed build outputs or on network credentials. Concurrency cancels superseded runs on work branches but not on master, so every master commit stays verified for the deploy that will key off it.

Two browser examples needed adjusting to run on Linux rather than only macOS — the title slide's emoji zoom and one hover tooltip; see [emoji zoom is not reproducible across Chrome builds](2026-09-30-emoji-zoom-is-not-reproducible-across-chrome-builds.md).
