## 2026-10-04 — TOC filter's position:sticky broke past one screen of flex stretch

**Context:** The Sprache/Genre filter bar (`#toc-filter`) is `position: sticky; top: 0` inside `#TOC`, which scrolls (`overflow-y: scroll`). With the real song book's 70+ entries, scrolling the list down by more than one screen's height made the filter bar scroll away with everything else instead of staying pinned — even though its computed `position` and `top` were exactly as intended. The existing browser spec only asserted those two computed values and never actually scrolled past a full screen, so it stayed green throughout.

**Decision:** Add `align-self: flex-start` to `section#TOC > .slide-content` in `night.css`, next to the existing `width: 100%` rule for the same element.

**Reasoning:** `post_process_index` configures Reveal with `display: 'flex'`, so every present slide — `#TOC` included — is a flex container. `.slide-content` is its single flex item, and flex's default `align-items: stretch` sizes a stretched item to the container's own cross-axis size: `#TOC`'s own height, i.e. the viewport, not `.slide-content`'s actual (much taller) content height. A `position: sticky` element only sticks while scrolling stays within its containing block; once `.slide-content` was capped at one screen's height, scrolling any further moved past that containing block entirely, so the sticky bar had nothing left to stick to and just scrolled off like a normal element. `align-self: flex-start` opts `.slide-content` out of the stretch and lets it grow to its real content height, restoring the sticky bar's intended containing block.

This surfaced only with a genuinely tall list (the small fixture book's 5 entries never overflowed a screen), which is also why the regression had gone unnoticed: the one browser spec covering this bar checked the right CSS properties but on a page too short to expose the bug. The fix for that is in [spec/browser/toc_filter_spec.rb](../spec/browser/toc_filter_spec.rb): shrink the browser window for that one assertion so even the small fixture overflows it, then scroll and check the bar's actual on-screen position — the same check that caught this on the live book.
