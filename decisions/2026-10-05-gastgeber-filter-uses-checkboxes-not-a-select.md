## 2026-10-05 — Gastgeber filter uses checkboxes, not a select, and a `role="group"` div instead of a nested `<fieldset>`/`<legend>`

**Context:** Adding a third TOC filter category, Gastgeber (host), alongside the existing Sprache/Genre `<select>`s. Unlike those two, a song can legitimately have more than one host, and the useful question when filtering is usually "show me the songs for *either* Josua's or Monika's evening," not "show me only songs tagged with exactly one specific host."

**Decision:** Gastgeber is a group of checkboxes (one per distinct host, sorted), combined with **OR** among themselves, then **AND**ed into whatever Sprache/Genre already narrowed down — unlike Sprache and Genre, which stay single-select `<select>`s AND'd together. The checkbox group itself is a plain `<div class="toc-filter-field toc-filter-checkboxes" role="group" aria-label="Gastgeber">` with a visible `<span class="toc-filter-checkboxes-label">` playing the same role Sprache/Genre's own `<label>` does — not a nested `<fieldset>`/`<legend>`.

**Reasoning:** A select only ever carries one value, so it can't express "either of two hosts" — checkboxes are the natural multi-choice control, and OR is the only combination that makes "pick two hosts" produce a non-empty, useful result (AND would require a song to list *every* checked host, which never happens since most songs have exactly one).

The nested-fieldset structure was the first attempt, mirroring `#toc-filter`'s own outer `<fieldset>`/`.visually-hidden <legend>` pattern. It broke a browser spec: `spec/browser/toc_filter_spec.rb`'s sticky-positioning test shrinks the window to 1280×100 to force the TOC past one screen, and a `<legend>` — even inside a fieldset with `display: flex` — is still rendered by both Chrome and Firefox as its own layout row ahead of the flex content, rather than participating in the flex layout like a normal child. That inflated `#toc-filter`'s total height to ~98px, almost exactly the 100px test viewport, which collided with the standard CSS rule that a `position: sticky` element yields (goes slightly negative) once sticking it fully would overflow past the end of its scroll container's content — `getBoundingClientRect().top` came back `-8` instead of `0`. Switching to a `role="group"` `<div>` with a visible label `<span>` sidesteps the quirk entirely: a `<div>` has no special child-layout behaviour, so it lays out as an ordinary single-row flex child like the two `<select>`s next to it, keeping the whole bar's height close to what it was before Gastgeber existed. `role="group"` + `aria-label` preserves the same "announced as a labelled group" semantics a `<fieldset>`/`<legend>` would have given a screen reader.
